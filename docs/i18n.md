# Internationalisation

Capturia uses the OpenScreen v1.7.0 layout: one JSON file per namespace per
locale, a dependency-free loader, and a React context. Call sites keep the
`useI18n().t("namespace.key")` contract.

## Layout

```
src/i18n/
  config.ts                 SUPPORTED_LOCALES, COMPLETE_LOCALES, I18N_NAMESPACES, LOCALE_STORAGE_KEY
  loader.ts                 import.meta.glob of locales/**, translate(locale, ns, key, vars)
  index.tsx                 public entry: useI18n, useScopedT, I18nProvider, normalizeLocale, ...
  locales/<locale>/
    common.json             app name, generic buttons, error toasts, playback, electron.* (tray, native dialogs)
    dialogs.json            export.*, tutorial.*, format.*, gif.*
    editor.json             editor toasts and chrome
    launch.json             HUD, source.* (source picker), permission.* (permission window)
    settings.json           settings panel, annotation.*, font.*
    shortcuts.json          shortcut labels and the config dialog
    timeline.json           timeline labels and toasts
src/contexts/I18nContext.tsx  provider, t(), useScopedT(), normalizeLocale(), storage
electron/i18n.ts              mainT(locale, "common.electron.tray.open") for the main process
scripts/i18n-check.mjs        parity + placeholder + call-site check (`npm run i18n:check`)
```

The namespace is the first dotted segment of a key: `t("timeline.addZoom")`
reads `timeline.json` -> `addZoom`. Files are nested JSON; a key that is both a
string and a prefix (`launch.shape` and `launch.shape.rounded`) keeps the
children as dotted keys next to the leaf, and the loader resolves either shape.

Lookup order: requested locale -> `en` -> the literal `namespace.key` marker.
`{{var}}` placeholders are interpolated from the `vars` argument; an unknown
placeholder is left as is.

## Locales

| Kind | Locales | Rule |
|------|---------|------|
| complete | `en`, `zh-CN`, `vi` | must stay in key parity with `en` (`i18n-check` fails otherwise) |
| partial | `ar es fr it ja-JP ko-KR pt-BR ru tr zh-TW` | only keys with an upstream translation; the rest fall back to `en`; `i18n-check` warns |

A locale becomes selectable in the HUD picker as soon as its folder contains all
seven namespace files (`getAvailableLocales()`), and is labelled with its own
`common.locale.name`.

The user's choice is persisted under `localStorage["capturia.locale"]`; the
renderer forwards every change to the main process through the `set-locale`
IPC so tray labels and native dialogs follow.

## Adding a key

1. Add it to `src/i18n/locales/en/<namespace>.json` and to `zh-CN` and `vi`.
2. Use it: `t("<namespace>.<key>")`, or `const t = useScopedT("<namespace>")`
   in components ported from upstream.
3. Optionally add it to partial locales when a translation is available.
4. `npm run i18n:check` - fails on a key missing from a complete locale, on a
   placeholder mismatch, or on a `t("...")` literal in `src/` that has no `en`
   value.

Strings the main process needs go in `common.json` under `electron.*` and are
read with `mainT(locale, "common.electron.<key>")`.

## Adding a locale

1. Create `src/i18n/locales/<tag>/` with all seven files (empty `{}` is valid
   for a namespace you have not translated yet) and set `common.locale.name`
   / `common.locale.short`.
2. Add the tag to `SUPPORTED_LOCALES` in `config.ts` and to the import table
   in `electron/i18n.ts`.
3. When the translation is complete, add it to `COMPLETE_LOCALES` and to
   `STRICT_LOCALES` in `scripts/i18n-check.mjs`.
