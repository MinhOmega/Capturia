# Gap report B1 — Webcam composite layouts, backgrounds, blur effects, 3D

Date: 2026-08-27. Read-only analysis. Refs: `/tmp/openscreen-base` (87735c27), `/tmp/openscreen-v1.7.0`, `/tmp/openscreen-upstream` (git). Capturia @ `feat/upstream-sync-v1.7` (main 4cab381).

## 0. The one architectural fact that shapes this whole stream

**Capturia burns the webcam into the screen recording at capture time. Upstream records it as a separate file and composites it in the editor.**

- Capturia WebRTC path: `src/hooks/useScreenRecorder.ts:506-570` opens the camera with `getUserMedia`, draws it onto the desktop canvas using `computeCameraOverlayRect()` (`src/hooks/cameraOverlay.ts`) and records the composited canvas.
- Capturia macOS native path: `electron/native/sckRecorder.ts:313-315` passes `--camera-enabled/--camera-shape/--camera-size-percent` to `sck-recorder.swift`, which composites the camera via `CIBlendWithMask` (`CameraCaptureProvider`, `composeCameraImage`) into the same output.
- Shape/size (`rounded|square|circle`, 14–40 %) are chosen in the HUD (`LaunchWindow.tsx:131-160`, persisted in `localStorage` as `capturia.cameraShape` / `capturia.cameraSizePercent`).
- Result: the editor has no webcam track. There is no `webcamVideoPath` in Capturia's `RecordingSession`, `VideoPlayback` has no `<video>` for the webcam, and `frameRenderer.ts` never receives a webcam frame. `cameraContainer` in Capturia's `VideoPlayback.tsx`/`frameRenderer.ts` is the Pixi *zoom camera* container, unrelated to the webcam.
- Upstream v1.7.0: `useScreenRecorder.ts:44` writes `<recording>-webcam.webm` via a second `RecorderHandle`; `electron/ipc/handlers.ts:329-337, 2071-2081, 2228` store `webcamVideoPath` in the session; `VideoEditor.tsx:237-238` loads it; `VideoPlayback.tsx:2096-2135` renders a positioned `<video>`; `frameRenderer.ts:1041-1140` draws the decoded webcam `VideoFrame` in export.

Consequence: every "webcam in editor" feature below (layout presets, movable PiP, size, mask, mirror, reactive zoom, Full Camera) is **blocked on stream A** producing a separate webcam sidecar recording (both in the WebRTC recorder and in the SCK helper, which would need to stop compositing and instead write a second file, or the renderer records the webcam with `MediaRecorder` in parallel like upstream's `d11eea04`/`5b67fd78`). Until that decision is made, these features are NOT-APPLICABLE, not MISSING. This report still documents them fully so the port can start the moment stream A lands.

Note for stream A: if the sidecar is adopted, the HUD shape/size controls become redundant with the editor controls (upstream keeps only a webcam device selector on the HUD, `0a5e57ce`). Keeping both would create two sources of truth.

## 2. Per-feature detail

### W. Webcam in editor (W1–W10) — blocked on stream A

**What upstream does.** `computeCompositeLayout({canvasSize, maxContentSize, screenSize, webcamSize, layoutPreset, webcamSizePreset, webcamPosition, webcamMaskShape})` returns `{screenRect, webcamRect: StyledRenderRect|null, screenBorderRadius?, screenCover?}`. Presets:
- `picture-in-picture` — screen centered (`centerRect`, respects padding via `maxContentSize`), webcam sized to `sqrt(w*h) * size%` (geometric mean so it looks the same in portrait/landscape), default bottom-right with 2 % margin, or at `webcamPosition` (center-normalised, clamped inside canvas). Circle/square force a square box; `rounded` uses 30 % radius, `circle` 50 %, else 12 % clamped 12–24 px. Shadow `0 10px 24px rgba(0,0,0,.35)`.
- `vertical-stack` — only offered when the canvas is portrait (`isPortraitAspectRatio(aspectRatio)` in `SettingsPanel.tsx:543`); webcam full-width at the bottom, screen fills the rest in cover mode; padding forced to 0 (`frameRenderer.ts:700`, `SettingsPanel.tsx:1532-1549`).
- `dual-frame` — only for landscape; 2:1 split with a 2 % gap, both slots rounded (`screenBorderRadius`), screen in cover mode.
- `no-webcam` — hides the webcam in preview and export.

Preview (`VideoPlayback.tsx`): `computeLayout` in `layoutUtils.ts` now takes `webcamDimensions/webcamLayoutPreset/webcamSizePreset/webcamPosition/webcamMaskShape` and returns `webcamRect` + `maskBorderRadius`; the webcam `<video>` is an absolutely positioned DOM element (`:2096-2135`) using `clipPath` (`getCssClipPath`) for circle and `borderRadius` otherwise, `object-cover`, `scaleX(-1)` when mirrored. The webcam element is kept in sync with the main video (`:1955-2022`: seek, play/pause, playbackRate incl. speed regions). Drag handlers `:793-838` emit `onWebcamPositionChange` during drag and `onWebcamPositionDragEnd` (history commit) on release.

Reactive zoom (`a806e34f`): per ticker frame the wrapper gets `transform: scale(reactiveWebcamScale(appliedScale))` with `transformOrigin` chosen from the docked corner (`:1483-1493`); floor 0.35. Export mirrors it in `frameRenderer.ts:1067-1086`.

Full Camera (`88669afc`): `CameraFullscreenRegion {id,startMs,endMs}`; `computeCameraFullscreenProgress(regions, t)` eases 0→1→0 strictly inside the region (lead-in `TRANSITION_WINDOW_MS`, lead-out 1.5x, both clamped to half the duration); `lerpRect(webcamRect, computeCameraFullscreenTargetRect(canvas, webcamRect), p)` gives the drawn rect; the target keeps the webcam's aspect and insets 2.5 % of the shorter canvas side. Timeline gets a new row, shortcut `C`, id counter `camera-fullscreen-N` (reset on new project, `05c2116c`), overlap guards (`501de43b`). Export blocks the source-copy fast path when such regions exist (`videoExporter.ts:151`).

Export (`frameRenderer.ts:1041-1140`): after drawing the screen, the decoded webcam `VideoFrame` is centre-cropped to the rect's aspect, clipped with `drawCanvasClipPath` (arc for circle, `roundRect` otherwise), shadowed per preset, and drawn via `drawWebcamFrameImage(ctx, frame, crop, dest, mirrored)` (mirror = translate + `scale(-1,1)` inside save/restore; test covers the restore-on-throw).

**Capturia mapping.** No counterpart in the editor. Record-time equivalents: `computeCameraOverlayRect` (`cameraOverlay.ts`, tested) and the Swift `computeOverlayRect/buildMaskImage/buildBorderImage`. `layoutUtils.ts` is the fork-base version (no `webcamRect`, no `maskBorderRadius`).

### B5 / B6. Wallpaper resolver + export error surfacing
Upstream final state (`d145f800` then `adf3855a`, `702b7330`, `f2ff7fb2`, `af159e8a`, `e06e40db`, `37331980`):
- `wallpaper.ts`: `WALLPAPER_PATHS`/`DEFAULT_WALLPAPER` single source of truth; `classifyWallpaper()` → `color | gradient | image` (handles `url(noise), linear-gradient(...)` composites, `repeating-*`, `oklch()` etc.); `resolveImageWallpaperUrl()` passes through `http/https/file/data`, otherwise requires the `/wallpapers/` prefix and calls `getAssetPath`; `BackgroundLoadError` (with `displayUrl` that never leaks a full path) and `UnsafeImagePrefixError`.
- `assetPath.ts`: now **synchronous** — the main process passes `--asset-base-url=file:///…/` through `webPreferences.additionalArguments` on every window (`windows.ts`), preload exposes `electronAPI.assetBaseUrl`; `encodeRelativeAssetPath` rejects `.`/`..` segments (incl. percent-encoded) and encodes each segment.
- `projectPersistence` persists the canonical `/wallpapers/wallpaperN.jpg` form, never the resolved `file://` URL (`f2ff7fb2`), with a legacy normaliser for old `file://…/assets/wallpapers/x.jpg` values (`af159e8a`, test `37331980` covers Windows drive letters).
- `frameRenderer.setupBackground` no longer swallows load errors; `videoExporter`/`gifExporter` short-circuit the retry loop on `BackgroundLoadError`; `VideoEditor` shows `errors.exportBackgroundLoadFailed`.

Capturia today: `assetPath.ts` is async over IPC (`get-asset-base-path` returns `<resources>/assets` or `<app>/public/assets`, `handlers.ts:1759-1768`; `electron-builder.json5:23-26` copies to `assets/wallpapers` — consistent, and `5e15088` made `frameRenderer` use it). `VideoEditor.tsx:312, 925-940` stores the **resolved** `file://` URL as `wallpaper` and in the project file (so a project moved between dev/packaged or machines points at a dead path); `VideoPlayback.tsx:1102-1134` re-resolves with its own prefix checks; `frameRenderer.ts:284` falls back to black silently.

Recommendation:
- Port `src/lib/wallpaper.ts` (+ the `classifyWallpaper`/`BackgroundLoadError` halves of `wallpaper.test.ts`, ~25 tests) and use `classifyWallpaper` in `VideoPlayback.tsx` and `frameRenderer.ts`. Adapt `resolveImageWallpaperUrl` to await Capturia's async `getAssetPath` (or port the sync preload arg together with stream F — it touches `electron/windows.ts` for every window and is the cleaner end state; the `resolveImageWallpaperUrl` tests that mock `electronAPI.assetBaseUrl` only work with the sync version).
- Port canonical persistence: keep `wallpaper` state as `/wallpapers/N.jpg` (or `#hex` / gradient / `data:`), resolve at render time, and add the legacy normaliser for existing Capturia projects that saved `file://…/assets/wallpapers/N.jpg`. This is a `ProjectState` semantic change, not a shape change; needs a migration test.
- Port the error path (throw + toast, i18n `errors.exportBackgroundLoadFailed`).
- Do **not** move `assets/wallpapers` → `wallpapers` (upstream "Smell D"); Capturia's layout is coherent and changing it only churns `electron-builder.json5`, the handler and installed-app upgrade paths.
Effort M total (S for the error path alone).

### T1. 3D iso/tilt
`ZoomRegion.rotationPreset?: 'iso'|'left'|'right'` → `ROTATION_3D_PRESETS` (iso −10°/−16°, left −22° Y, right +22° Y). `getRotation3D`, `lerpRotation3D`, `isRotation3DIdentity`, `computeRotation3DContainScale` (projects the 4 corners through the CSS perspective `P = 2.6 * min(w,h)` and returns the scale that keeps the rotated box inside its own rect), `rotation3DPerspective`.
- Preview (`VideoPlayback.tsx:1849-1893`): the Pixi canvas + cursor canvas are wrapped in `outerWrapper` (gets `perspective: Ppx`) and `composite3D` (gets `scale(s) rotateX() rotateY() rotateZ()`), driven per ticker frame from `findDominantRegion(...).rotation3D` lerped by zoom progress; the native-cursor clip div copies the same transform (`85167078`). Background stays flat.
- Export (`threeDPass.ts`): a WebGL2 quad pass with the same MVP (`buildMvpMatrix`: rotZ·rotY·rotX, contain scale, perspective from `fovY = 2·atan2(h/2, P)`), premultiplied upload, anisotropic filtering, no mipmaps; `frameRenderer.ts:453-495` runs the foreground canvas (video + shadow + webcam) through it and draws the result onto the background; `readPixels()` fallback exists for platforms where `drawImage(webglCanvas)` is unreliable. `zoomRegionUtils.ts` carries `rotation3D` through `findDominantRegion` and region-to-region transitions.
- UI: `SettingsPanel.tsx:1116-1140` preset buttons under the zoom section; i18n `zoom.threeD.title`, `zoom.threeD.preset.{iso,left,right}`, `zoom.threeD.none`.
- Capturia: nothing. `zoomRegionUtils.ts` is the 2-function fork-base version (367-line diff vs upstream, most of it customScale/focusMode/transition work owned by stream B2). Capturia draws subtitles and the composited cursor on the composite canvas — decide whether they rotate with the video (upstream rotates cursor, not annotations).
- Schema: `rotationPreset` optional; normaliser accepts only the 3 strings. Effort L. Order: after B2 has synced `zoomRegionUtils`/`findDominantRegion`, otherwise the port has to re-do that work.

### M1 / M2. Motion blur
Upstream final state (`zoomTransform.ts:150-245`): `motionBlurAmount ∈ [0,1]`; per frame compute camera velocity (translation + scale-change term), `targetBlur = (min(1, speed/1400))² · 14px · amountResponse(amount)` with `amountResponse = a·(1 + 1.2a)`, threshold 12 px/s, `MotionBlurFilter.velocity` along the motion direction scaled 2.4×, `kernelSize` 7/11/15, `offset −0.2`; the plain `BlurFilter` is kept at 0 (legacy). State in `createMotionBlurState()` (prev cam x/y/scale, last time, initialised) — reset when not playing. Ticker only touches `videoContainer.filters` when the active flag changes (`lastMotionBlurActive`), and sets `filters = null` when idle. Export: `frameRenderer.ts:228` attaches both filters permanently (acceptable there, every frame is rendered anyway).
- Capturia: `zoomTransform.ts` isotropic `BlurFilter.strength` from `motionIntensity` (a focus-delta heuristic from `VideoPlayback`), toggle `motionBlurEnabled`, and `VideoPlayback.tsx:857` keeps `[blurFilter]` attached at all times — this is the "pixi render blur" upstream fixed in `90d04c73`.
- Port M2 alone first (S): create the filter but only assign `videoContainer.filters` while blur is active, mirror the `lastMotionBlurActive` caching. Visible sharpness win in preview.
- Port M1 (M): add `pixi-filters@^6.1.5` (needs pixi.js ≥ 8; Capturia is on 8.14 — fine), replace Capturia's `applyZoomTransform` blur block with upstream's (keep Capturia's signature otherwise; B2 will likely replace the whole function later), slider in `SettingsPanel.tsx:565-575`, `motionBlurAmount` through `VideoEditor` → `VideoPlayback`/`videoExporter`/`gifExporter`/`frameRenderer`.
- Schema migration: `ProjectState.motionBlurEnabled: boolean` → add `motionBlurAmount?: number`; on load `amount = typeof s.motionBlurAmount === 'number' ? clamp01 : (s.motionBlurEnabled ? 0.35 : 0)`; keep writing `motionBlurEnabled = amount > 0` for one release so a downgrade still reads something sensible. Unit-test the mapping.
- Upstream tests: none for `zoomTransform`; write one for `getMotionBlurAmountResponse` bounds and for the state reset.

## 4. Do NOT port / keep Capturia's version

- **Record-time webcam compositing (`cameraOverlay.ts`, `sck-recorder.swift` overlay, HUD shape/size controls)** — keep until stream A decides on a sidecar. Do not port W1–W8 on top of a burned-in webcam: the editor would draw a second camera over the baked one.
- **Asset directory layout** (`resources/assets/wallpapers`, `get-asset-base-path` returning `.../assets`) — Capturia's `5e15088` already makes dev and packaged consistent; upstream's flattening (`d145f800` Smell D) adds churn with no user-visible gain.
- **`98a32372` export composited shadow fix** — a revert of upstream-only code; Capturia's shadow path is the fork-base one and correct.
- **`90d04c73` codec order** — Capturia already prefers h264 and additionally lists `video/mp4;codecs=h264`; keep ours.
- **Blur regions (X1)** as shipped — upstream disabled it in the release we are syncing to and never re-enabled it in this architecture. Only port if product explicitly asks; then treat as new feature work with our own QA.
- **`446e3a35` motion-blur history checkpoint fix** — Capturia's undo model does not snapshot appearance settings; nothing to fix. Re-evaluate if B3 adopts upstream's `useEditorHistory`.
- **Background blur (`showBlur`)** — Capturia's `src/lib/rendering/backgroundBlur.ts` (preview 2 px, export scaled to output width, pre-baked once) is more consistent than upstream's fixed `blur(6px)` per frame (`frameRenderer.ts:1000`). Keep ours.
- **Capturia's async `getAssetPath` signature** unless stream F ports the sync `additionalArguments` plumbing; a half-port (sync in some callers, async in others) is worse than either.
